# V35：单文件夹样品分析与前后对比

V35 基于 V34 的独立脚本，保留其 V27 定位、Yakun 原灰度边缘验证、有限补检、四排 slot 完整列和 300 秒独立进程时限。内部 `_v32_*` 等名称表示继承流程，不需要运行或导入旧版脚本。

## V35 模式、清单与执行流程

`main_v35(before_root=None, after_root=None, output_root=None, ..., *, input_root=None, mode=None)` 是共享批处理入口。提供 `input_root` 时默认 single，否则默认 compare。CLI 对应 `--input`、`--mode single|compare`；保留 `--before` / `--after` 命令。模式冲突与无效检测参数在创建输出目录前报错。非空输出目录被拒绝，防止重跑或切换模式时混入旧统计图。

- **single**：`_v35_build_single_inventory` 从 input 根目录发现直接数字子目录，完整名称即独立样品编号，按数字值排序，保留前导零。没有前后对应或样品间数量相等要求。空样品记 `EMPTY_SAMPLE_FOLDER` 后继续；所有样品无图时写出诊断并报错。
- **compare**：沿用 AFTER 发现、BEFORE 精确同名匹配与数量一致性检查，缺目录/数量不等时跳过该条件。
- 两种模式均按图片文件名自然排序，每三个位置映射 trench、slot、via，从 Region 2 开始。允许尾部不完整组；图片类型不从文件名语义猜测。缺失中间图片会导致后续位置改变，应由使用者整理输入并核对 inventory。
- TXT 预检失败不删除 inventory 行、不改变后续位置。single 仅跳过这张图；compare 跳过对应前后组。单图 worker 失败或超时继续其余图片。

single 使用独立的 `stage="single"` / 中文“样品”，不会将图片伪装成 before 或 after。检测器沿用原有通用（before）分支，历史仅 AFTER 触发的增强不用于 single。轮廓、四排完整性、质量筛选及尺寸测量逻辑不变。`condition` 在单模式表示样品编号，`pair_key` 只作为编号/Region/图案的兼容分组标识，不执行配对。

每张图在独立 Python 子进程中运行，继续使用硬时限 `(0,300]` 秒、默认 300 秒；耗时预算包括两级补检和 auto 模型尝试。single 的 auto 对每张 via 独立尝试 via40/via60 并复用最优测量与标注，不影响其他图片；compare 仍由 BEFORE 选定并冻结给同组 AFTER。单模式模型记录使用 `image` 和 `stage`，不产生 before/after 图片列。

## V35 统计与作图

单图统计共用 `_v32_build_image_metrics`，六项指标与 V34 一致：trench 宽度/端点间隙、slot 最下排 X 宽度/Y 长度、via X 宽度/Y 高度，单位 nm。只消费通过筛选的对象。

`_v35_build_sample_summary` 按 condition/pattern 合并所有 Region 的对象。每个指标计算 n、mean、样本 SD（ddof=1）、SEM、median、min、max，并统计有有效值的 image_count / region_count。它遵循原 overall 汇总的对象权重，不做“各图均值的等权平均”。例如两张图的有效值分别为 `[10,14]`、`[30]`，样品均值为 18，而非 21。

`_v35_save_single_plots` 按以下三种视图生成 220 dpi PNG；柱高是均值，误差棒为样本 SD，保留 nm、网格与区域排序：

1. 单个样品按 Region 展示，`C编号__图案__指标__single.png`。
2. 全部样品/Region 总览，`ALL__图案__指标__single.png`。
3. 各样品合并区域汇总，`SAMPLES__图案__指标__single.png`。

n=1 时表中 SD/SEM 为 NaN（CSV/Excel 显示空值），图上误差长度为 0；无有效测量的指标不生成统计行和柱。样品编号在图表中按数值排序，007 与 7 保持独立。compare 仍调用原 `_v32_save_pair_plots`，保留前后柱与 After−Before 差值图。

共享表清单同时驱动 CSV 和 Excel 导出，防止两者内容分歧。single 额外导出 `sample_metric_summary.csv` / `sample_summary` 工作表，不调用三个 before/after 比较构造器、不输出差值/变化率文件或比较工作表。无有效测量时单模式统计表仍保留可读取表头。`settings.json` 记录 mode、实际输入根目录、样品发现/数量规则、聚合权重、作图规则、auto 作用范围及测量参数。

## V35 直接验证

`tests/test_v35_single.py` 实际导入 V35。覆盖数字目录/前导零、多格式自然排序、不同样品图片数量、空目录、比例尺错误保留原位置、模式冲突、非空输出拒绝、样品汇总权重、n=1 的空 SD、图轴顺序/柱高/实际误差线、CSV/XLSX 格式和 compare 兼容。测试隔离故障还覆盖超时与损坏图片后继续、各样品独立 auto 和 compare 模型冻结。

真实 CLI 测试以中文/带空格目录输入两个合成样品：007 有 trench/slot/via，PixelSize=2；10 只有 trench，PixelSize=1。独立 worker 和 auto 实际运行，保留 41 个有效对象，生成 20 张图及 Excel/CSV/标注；trench 宽度/间隙分别接近 40/120 nm 与 20/60 nm，slot 最下排接近 34/42 nm，via 接近 80/80 nm。测试同时验证宽度/长度容差传入 worker，原有比例尺换算未被模式改变。空白图实际执行后无测量，极短硬时限终止 worker 且不发布部分标注。

完整仓库回归命令：`MPLBACKEND=Agg python3 -m unittest discover -s tests -v`。合成验证不代表本批真实 SEM 原图的准确率已确认；本仓库没有该批原图与 TXT。

## 继承的尺寸参数与数据流

`V35DetectionOptions` 统一验证参数：尺寸为有限正数，圆形度为 0–1，同图尺寸偏差为 `[0, 1)`（0 关闭），两类尺寸容差均为 `(0, 1]`。默认 `width_tolerance=0.50`，应用于 via 直径及 slit/trench 宽度；默认 `length_tolerance=1.00`，应用于最下排 slit 长度和 trench 端点间隙。CLI 接收 `slit` 及 `slot` 的同义参数名，`--gap-tolerance` 是 `--length-tolerance` 的同义写法。

旧参数 `size_tolerance` 默认为 `None`，显式设置时作为两类容差的统一后备值。独立指定的宽度或长度容差优先；未指定统一值时才使用 0.50 / 1.00。解析后的两类有效数值存入不可变参数对象，再序列化至 worker、`settings.json` 和 `input_width_tolerance` / `input_length_tolerance`。旧统一参数是否指定也保留在记录中。

最终范围检查使用 `|实测值 / 预计值 − 1| <= 对应容差`，并要求实测值有限且为正。100% 容差允许正尺寸至预计值两倍，但不能接受零长度、负间隙或虚构边缘。trench 端点搜索继续要求下端点至少在上端点之后超过 1 px。

`main_v35(..., detection_options=...)` 接受该对象或字典，将其序列化到每张图的 worker 请求。worker 在可恢复的上下文中应用参数，BEFORE 或 single 的 auto 两次模型尝试共享相同配置及单图预算。尺寸按各图 `PixelSize` 独立换算，图像处理失败时恢复上下文；不把上一张图的比例尺或参数遗留到下一张图。超出图像物理范围的尺寸提示明确报错。

## via：只在最终原图轮廓上应用用户阈值

1. 定位及原图轮廓细化沿用 V32。前期固定圆形度门槛不会比用户阈值更严格；最终仍须通过原图信号、solidity、长宽比、阵列及边界检查。
2. 对最终浮点轮廓重新计算 `C = 4πA/P²`，`C < via_min_circularity` 时剔除。默认 0.75；调整该参数只影响 via。补检等级不会覆盖该阈值。
3. 计算等效直径 `D = 2√(A/π) × PixelSize`。若填入预计直径，则检查 `D` 是否位于预计值的 `1 ± width_tolerance` 范围内。
4. 从通过上述检查的同图对象计算一次中位直径 `M`，若至少有 3 个孔且启用尺寸偏差筛选，则剔除 `|D/M−1| > via_max_size_deviation` 的对象。默认 0.30，不做反复中位数裁剪。对象不足时记录跳过。同图参考不会来自另一张图或另一阶段。
5. 重新拟合保留对象的坐标轴，沿用 V32 的跨度验证，重新分配 object ID。标注、CSV、Excel 和后续统计都消费保留后的同一组对象。剔除对象及阈值写入 `rejected_objects.csv`。

默认设置是通用起点，并非真实 SEM 数据标定结果。像素分辨率和轮廓噪声会影响圆形度；提高阈值会减少保留孔数。原来的其他形状条件仍有效，降低圆形度阈值不保证所有非圆形物体都能通过。

## 尺寸提示真正参与定位

- **via 直径**：优先作为像素搜索尺度；匹配模板在宽度容差内取多个尺度，候选不足时仍能使用用户尺度。未填时继续使用图内候选中位直径 / 标称回退机制。最终 CD 来自轮廓，与输入直径独立。
- **slit 宽度 / 长度**：新增尺寸辅助候选生成。宽度控制横向去背景形态学窗口、候选宽度范围及缺失格点候选评分，长度辅助纵向平滑。候选来自实际图像掩膜，不直接生成测量矩形。候选合并到原有四排定位，再用原图轮廓法复核；最终仅统计完整列的最下排。长度范围使用独立的 `length_tolerance`，只用于最下排，避免删除真实长度不同的其他三排。
- **trench 宽度**：控制垂直暗条背景尺度、横向峰抑制距离及局部边缘搜索窗口，边缘窗口由 `width_tolerance` 扩展，搜索受邻条间隔限制。
- **trench 间隙**：在上下端点搜索区域中寻找方向相反、对比度足够的真实灰度跃迁，选择间距在 `length_tolerance` 内的端点对；随后仍执行原图宽度/端点验证。
- 只对填入的维度检查最终尺寸范围；所有原图证据门槛继续生效。容差不是测量误差估计，也不把实测值吸附到输入值。

尺寸提示在一次运行中对所有样品/条件及实际运行阶段生效。如果希望允许较大的真实前后变化，应相应放宽容差、调整或省略该项提示。slit/slot 在结果表中继续使用 `slot`，保持现有下游格式。

## 输出与可追溯性

`settings.json` 保存 `detection_options`、圆形度定义、同图参考规则和 slit 长度作用范围。对象与拒绝记录中的 `input_*` 保存所用参数；有效 via 还记录等效直径、中位直径、参考数量、相对偏差以及是否应用尺寸筛选。图像状态包含筛选数量及补检信息。

实际入口为 `main_v35`；single 工作簿为 `SEM_0830_0831_single_V35_results.xlsx`，compare 工作簿为 `SEM_0830_0831_before_after_V35_results.xlsx`。历史兼容列如 `selected_v25_pattern_key` 保留。

## V34/V33 继承验证基线与限制

`tests/test_v34_tolerances.py` 实际加载 V34，覆盖拆分容差及真实测量流程。历史版本测试保持原样并纳入仓库回归；V33 的测试结果仅作为继承基线，不能代替 V35 新流程的直接验证。

V34 验证包含默认值与自定义值、统一参数兼容及优先级、序列化往返、无效参数在创建输出前报错、边界值、零/负/非有限尺寸拒绝，以及真实 worker 的每图比例尺和两类参数传递。

合成 slit 实测最下排长度约 21 nm，分别提示 12 nm、50 nm；trench 实测间隙约 60 nm，分别提示 35 nm、140 nm。默认 100% 容差允许这些超过 50% 的偏差，收紧到 50% 时剔除。宽度和 via 直径仍按独立的 50% 范围筛选；空白图仍无有效对象。

V33 已有合成验证基线包括：

- 20 个孔中包含 1 个直径 56 px 的异常孔、其余 19 个直径 40 px：关闭尺寸筛选时保留 20 个；最大偏差 0.20 时保留 19 个，剔除原因和统计数量一致。
- 低对比、带背景梯度的 slit 图额外施加 3.5 px 高斯模糊：无尺寸提示时无完整有效列，提供 17 × 21 nm 的最下排尺寸后恢复 2 列；仍需四排及至少 85% 原图边缘支持。
- 输入预计直径 90 nm 的 via 图，真实直径 80 nm：独立 worker 输出约 80 nm，且记录预计值为 90 nm，不把结果强制设成提示值。
- 输入 trench 预计宽度 44 nm、间隙 130 nm，实际 40/120 nm：检测仍按原灰度边缘测得接近真实值。
- via 圆形度设 1 时，常规及两级补检均不能绕过阈值；设置 via 阈值不影响 slit/trench。
- 提供完整尺寸提示的空白图仍无有效对象。

目前没有本批真实 SEM 图像及比例尺文件，因此以上是合成图与程序流程验证。严重模糊可能无法提供可靠边缘，尺寸提示不保证恢复全部对象；圆形度和尺寸范围也可能排除真实形变，使用时应结合剔除日志和标注复核。
