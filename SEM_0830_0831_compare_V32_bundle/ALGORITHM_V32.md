# V32 尺寸策略与验证

V32 修正 V31 默认自动选择 via40/via60 与本批明确为 via60 的需求不符的问题。
它继承 V31 的 V27 定位、Yakun 原图灰度边缘和 V30 有限补检流程，单文件独立运行。

## V31 问题来源

V31 的 `--via-pattern` 默认 `auto`。via40/via60 分别使用 40/60 nm 标称直径，
影响中心搜索、边缘窗口、形状筛选和最终跨度范围，不是两个等价的标签。
常规跨度范围为标称值的 0.72–1.50 倍；via40 因而只允许 28.8–60 nm，
via60 也只有 43.2–90 nm。零结果补检放宽到最高 1.60 倍，仍依赖标称直径。
自动选择以阵列、是否补检、检出数量等优先排序，不保证选中用户已知的图案型号。

## V32 的 via 处理

1. CLI 与 `main_v32` 默认 `via60`，把同一型号传给 BEFORE 与 AFTER 的独立 worker。
   只有显式 `--via-pattern auto` 才进行双模型试算；`via40` 仍保留供明确需要时使用。
2. `_v32_via_search_scale` 从候选池中筛选完整、solidity ≥ 0.70、circularity ≥ 0.35、
   aspect ≤ 1.8、等效直径 ≥ 6 px、面积不超过图像 10% 的近圆候选。
   对同一中心的重复候选去重，再用中位直径的 0.65–1.50 倍范围去除尺度离群值。
   至少 4 个候选支持时使用其中位等效直径；否则使用该型号的标称像素尺度。
   这是定位尺度估计，不是最终验收，也不把候选外形强制改成圆。
3. 实际搜索尺度传入中心响应、阵列拟合、径向边缘提取和形状检查。
   模板保留搜索尺度附近的 0.80、0.90、1.00、1.10、1.22 倍；基准随实际候选孔径变化。
   避免过大的环形模板覆盖相邻孔而拉偏中心，较大像素孔径测试覆盖此问题。
   初始候选等效直径允许搜索尺度的 0.50–2.00 倍；轮廓等效直径上限放宽为 2.00 倍。
4. 中间和最终 X/Y 跨度按图中搜索尺度筛选，常规 0.50–2.00 倍；
   补检 L1 为 0.45–2.10 倍，L2 为 0.40–2.20 倍。
   范围不再乘以标称 60 nm，因此没有 90/96 nm 的固定尺寸截断。
   实际可检范围仍受相邻目标间距、径向信号支持、图像边界及形状约束限制。
5. V31 原图灰度 50% 轮廓细化和审核保持：至少 85% 边缘支持，短缺口插值，
   几何变化约束、solidity、circularity、aspect、ellipse IoU、radial CV 和阵列约束保留。
   最终尺寸是最终轮廓在拟合坐标轴上的跨度乘以 PixelSize，不把 CD 固定为 60 nm。
6. BEFORE 与 AFTER 的标称型号一致，图中搜索尺度独立估计，允许处理后孔径变化。
   型号和尺度分别记录，避免把标称值、搜索值和最终 CD 混为一谈。

所有补检仍需经过原图证据检查。V31 的 8 位原灰度、高位深浮点线性换算、
局部背景斜率校正、闭环追踪、超时子进程隔离规则继续生效。
候选不足时回到标称尺度，不代表一定能找回任意大的弱对比孔；结果中记录此回退。

## slot 与 trench 的尺寸审查

slot210/trench160 中的 210/160 用于内部图案键，没有按它们设置 nm 级尺寸上限。
V32 放宽实际生效的图内相对尺寸过滤：

| 约束 | V31 | V32 |
| --- | --- | --- |
| slot 相对平均面积 | 0.10–10.0 倍 | 0.05–20.0 倍 |
| slot 低灰度和背景校正候选的图像面积占比上限 | 3.5% | 10% |
| trench 宽度相对中位数容差 | 55% | 85% |
| trench tip gap 相对中位数容差 | 34% | 80% |
| trench 宽度/gap 的 MAD 系数 | 5 | 7 |
| trench L1 宽度/gap 容差 | 68% / 42% | 95% / 90% |
| trench L2 宽度/gap 容差 | 82% / 52% | 110% / 100% |

trench 异常值门槛仍取相对容差、MAD 门槛和 2.5 px 中的最大值。
slot 的最小像素面积、四行完整性、阵列位置和形状标准保留。
trench 的有效灰度边缘、上下配对、正 gap 以及局部细化位移限制保留。
局部细化约束比较的是同一张图上的定位候选，不是和 160/210 nm 比较。
形状和边缘检查不能用放宽 CD 门槛替代。

## 输出

版本、工作表文件、注释图输出目录均为 V32。
`selected_pattern_key` 是最终采用型号；`selected_v25_pattern_key` 为兼容旧表保留的同义字段。
`via_nominal_diameter_nm/px` 保留标称含义；`via_search_diameter_nm/px` 单独记录搜索尺度。
`via_search_scale_source` 为 `candidate_pool_median` 或 `nominal_fallback`，
`via_search_scale_candidate_count` 记录支持数，`x_width_nm/y_height_nm` 是最终实测值。
图像状态中的测量元信息带 `measure_` 前缀。
`settings.json` 记录 `via_pattern_mode` 与 `cd_filter_policy`。
模型选择表改名为 `via_model_choice.csv`，默认只记录 via60。

## 验证与范围

`tests/test_v32.py` 继承 V31 的边缘精度、旋转轮廓、低对比背景、缺行拒测、
标注、原图读取、真实子进程超时、auto 共享预算和超时后继续处理测试。
新增默认 via60 的 before/after 分派、65/100/120/240 nm via、较大像素直径孔、
完整分割与独立 worker、无边缘空白拒测、slot/trench 超过 210/160 nm、补检参数恢复测试。
via 的解析边界容差为 0.7 px；物理尺寸容差按 PixelSize 换算。
这些是合成图和流程验证，仓库中没有本批真实 SEM 原图与 PixelSize TXT。
不能把测试通过解释成该批 SEM 的绝对精度保证，也不能把局部灰度 50% 边界
直接视为材料边界的物理标定。放宽尺寸筛选后仍应复核标注及 `edge_*` 字段。

V31、V30、V29 及上传的 V27/Yakun 包保留。继承算法及来源校验值见
[V31 算法说明](../SEM_0830_0831_compare_V31_bundle/ALGORITHM_V31.md)。
